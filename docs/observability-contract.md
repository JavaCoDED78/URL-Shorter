# Observability Contract

**Version:** 1.1.0 — Sprint 29, Task 29.2 (Prometheus format fix)
**Status:** approved
**Date:** 2026-09-29

All business metrics are exposed through `MetricsRecorder` in `domain.service`.
Every metric has a stable name, type, unit, and an explicit set of labels.
Prometheus exposition via `/actuator/prometheus` follows Micrometer conventions.
The `urlshorter.` prefix is used as a Micrometer namespace separator, which gets
converted to `_` in Prometheus format (e.g. `urlshorter.linksCreated` →
`urlshorter_linksCreated_total`).

---

## 1. Business counters

All counters are **monotonically increasing** `io.micrometer.core.instrument.Counter`.
Prometheus name is the Micrometer name plus the `_total` suffix for counters.

| Metric name (Micrometer) | Prometheus name | Type | Unit | Labels | Semantics |
|---|---|---|---|---|---|
| `urlshorter.linksCreated` | `urlshorter_linksCreated_total` | counter | total | `application` | A short link was successfully created (both generated code and custom alias paths). |
| `urlshorter.linksRedirected` | `urlshorter_linksRedirected_total` | counter | total | `application` | A valid, non-expired link was resolved and returned 302. One increment per redirect, regardless of cache hit or miss. |
| `urlshorter.linksNotFound` | `urlshorter_linksNotFound_total` | counter | total | `application` | Redirect or details request returned 404 — no link found for the given code. |
| `urlshorter.linksExpired` | `urlshorter_linksExpired_total` | counter | total | `application` | A redirect was attempted on a link whose `expiresAt` has passed (410 Gone). |
| `urlshorter.linksDeleted` | `urlshorter_linksDeleted_total` | counter | total | `application` | A link was successfully deleted. |
| `urlshorter.cacheHit` | `urlshorter_cacheHit_total` | counter | total | `application` | A redirect resolved the link from the Redis cache (cache-aside hit). |
| `urlshorter.cacheMiss` | `urlshorter_cacheMiss_total` | counter | total | `application` | A redirect did not find the link in Redis and had to fall through to PostgreSQL. |
| `urlshorter.clicksIncremented` | `urlshorter_clicksIncremented_total` | counter | total | `application` | A click counter was successfully incremented in Redis. |
| `urlshorter.clicksIncrementFailed` | `urlshorter_clicksIncrementFailed_total` | counter | total | `application` | A click could not be counted because Redis was unavailable (best-effort analytics drop). |
| `urlshorter.clicksFlushed` | `urlshorter_clicksFlushed_total` | counter | total | `application` | Total drained click count persisted to PostgreSQL. Each flush call increments by the sum of drained counters (task 8.4, `CounterFlushService`). |
| `urlshorter.rateLimiterDenied` | `urlshorter_rateLimiterDenied_total` | counter | total | `application` | A create-rate-limit probe was denied (Task 20.4). Incremented only when the enabled limiter rejects a probe; a Redis outage fails open and does not increment it. |
| `urlshorter.clicksFlushFailed` | `urlshorter_clicksFlushFailed_total` | counter | total | `application` | A flush cycle failed (either Redis drain or PostgreSQL batch update). |

## 2. Business timers

All timers use Micrometer `Timer` (prometheus: `*_seconds` bucket histogram + `*_seconds_count` + `*_seconds_sum`).

| Metric name (Micrometer) | Prometheus name | Unit | Labels | Semantics |
|---|---|---|---|---|
| `urlshorter.redirectDuration` | `urlshorter_redirectDuration_seconds` | seconds | `application` | End-to-end time for a redirect resolution (controller → `ReadLinkService.resolve`), including cache, DB, and Redis lookups. |
| `urlshorter.postgresLookupDuration` | `urlshorter_postgresLookupDuration_seconds` | seconds | `application` | Time spent in a PostgreSQL lookup during a redirect cache-miss path. |
| `urlshorter.redisLookupDuration` | `urlshorter_redisLookupDuration_seconds` | seconds | `application` | Time spent in a Redis cache-aside lookup during a redirect. |

## 3. Platform metrics (provided by Micrometer/Spring Boot)

These are auto-generated by Micrometer when the Prometheus registry is present.
They are not owned by the application but are part of the operational picture.

| Category | Examples |
|---|---|
| **JVM** | `jvm_memory_used_bytes`, `jvm_gc_pause_seconds`, `jvm_threads_live`, `jvm_threads_daemon` |
| **Process** | `process_cpu_usage`, `process_jvm_memory_used_bytes`, `process_files_open_files`, `process_jvm_memory_committed_bytes` |
| **HikariCP** | `hikaricp_connections_active`, `hikaricp_connections_pending`, `hikaricp_connections_timeout_total` |
| **Tomcat** | `tomcat_sessions_active_current`, `tomcat_threads_config_max` |
| **HTTP server** | `http_server_requests_seconds_count` / `sum` / `max` (tagged with `http_request_method`, `http_response_status_code`, `uri`) |

## 4. Label policy

### Allowed labels

| Label | Source | Values |
|---|---|---|
| `application` | Hardcoded in `MeterFilter` | `"URL-Shorter"` |
| `service` | Optional — for multi-service deployments | `"url-shortener"` |
| `environment` | Configurable (`SPRING_PROFILES_ACTIVE`) | `"local"`, `"test"`, `"staging"`, `"production"` |

### Forbidden labels (high-cardinality — never used)

- `code` (short link code / alias)
- `originalUrl` / `url`
- `username` / `userId`
- `requestId` / `traceId` (propagated via OTel, not as a metric label)
- Any user-provided or arbitrary value

The `http_server_requests` metric from Spring Boot's built-in HTTP timers uses
`http_request_method`, `http_response_status_code`, and `uri` labels.
These are considered bounded because method is small-set, status code is small-set,
and `uri` is templated (e.g. `/{code}` not `/<actual-code>`).

---

## 5. Units

| Unit | Applied to |
|---|---|
| `total` | All counters |
| `seconds` | All timers |
| `bytes` | Platform metrics (JVM memory, process) |

Timers use the Micrometer default histogram: Prometheus records `_bucket` (le-labelled), `_count`, and `_sum` series.

---

## 6. Monotonicity guarantee

All counters are monotonic. The `clicks_flushed` counter increments by the **total
drained count** (sum of all per-link drained values), not by the number of links
flushed. This means the counter value represents the cumulative number of clicks
persisted to PostgreSQL across the lifetime of the application.

---

## 7. Verification

Each counter and timer above is verified by integration tests that assert
counter values change correctly through the create → redirect → expire →
delete → flush lifecycle (`infra/observability/ObservabilityIT`). The
`urlshorter.rateLimiterDenied` counter is additionally verified end-to-end by
`infra/redis/limiter/RedisRateLimiterIT`, which enables the real limiter and
confirms that a denied probe increments the metric.

---

## 8. Change procedure

Any change to this contract (new metric, renamed metric, new/removed label)
requires:

1. Update `MetricsRecorder` (source of truth).
2. Update this document.
3. Update the related integration test.
4. Update Grafana dashboard and Prometheus rules (in `monitoring/`) to reflect
   the new contract.
